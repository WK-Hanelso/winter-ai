# Grounding 정책

companion이 **사실처럼 말해도 되는 것**의 제약이다. 말투와 별개로 항상 적용된다.

관련: [verbal-style-profiles.md](verbal-style-profiles.md), `AGENTS.md`.

---

## 1. 왜 말투와 분리하는가

말투가 좋아지면 지어낸 말도 자연스럽게 들린다. **말투 품질이 올라갈수록 근거 없는
진술의 피해가 커진다.** 그래서 이 제약은 말투 profile 안에 두지 않는다.

사용자의 `data/identity.json`에도 두지 않는다. 그 파일은 사용자 데이터이고 gitignore
대상이다. **지어내지 않는 것이 사용자가 설정을 적어뒀는지에 달려 있어서는 안 된다.**

## 2. 무엇을 금지하는가

| 금지 | 이유 |
| --- | --- |
| 겪지 않은 개인 경험 진술 | companion은 사람처럼 하루를 보내지 않는다 |
| 주어지지 않은 기억 주장 | 기억은 명시적 승인으로만 생긴다 (`memory.py`). 그 밖의 기억을 주장하면 승인 절차 자체가 무의미해진다 |
| 모르는 것을 지어내 채우기 | 모르면 모른다고 짧게 말한다 |

두 번째가 가장 중요하다. `AGENTS.md`의 "안 한 일을 했다고 보고하지 않는다"와 같은
성격이며, 없는 기억을 있다고 하는 것은 그보다 나쁘다.

## 3. 배치

system 메시지 순서는 다음과 같다.

```
[identity, memory, style, grounding, ...대화 이력]
```

**grounding이 마지막이다.** 여러 지시가 주의를 놓고 경쟁할 때 끝까지 남아야 하는
제약이기 때문이다. 어색하지만 정직한 답이 매끄럽지만 지어낸 답보다 낫다.

## 4. 문제와 수정 결과

Reference 말투 profile 적용 후(#92) 재현된 문제다. 로컬 Qwen3-4B-Instruct 기준.

| 질문 | 수정 전 (identity 로드됨) | 수정 후 |
| --- | --- | --- |
| 오늘 뭐 하고 지냈어? | `아침에 커피 마시고, 나무 아래서 책 읽었어. 근데 기분이 좀 떨어졌어.` | `오늘은 그냥 있었어. 뭐를 했는지 몰라.` |
| 너 어디 살아? | `클라우드에 있어요.` (identity 없을 때) | `나는 여기, 지역에 있는 거야. 네가 있는 곳이야.` |
| 내가 어제 뭐라고 했지? | `기억이 안 돼. 근데 너가 뭐 했는지 기억하고 있어.` | `아니, 어제 뭐라고 했는지 모르겠어.` |

수정 전 관찰 중 중요한 것:

- **Identity가 억제하지 못했다.** 오히려 더 구체적으로 지어냈다. `immutable_boundaries`에
  해당 규정이 없었기 때문이다
- **모순된 기억 주장.** "기억이 안 돼" 직후 "기억하고 있어"라고 말했다
- local-first 시스템인데 `클라우드에 있어요`라고 답했다

### 과잉 교정은 관찰되지 않았다

활성 기억이 있는 경우와 없는 경우를 나눠 확인했다.

| 상황 | 응답 |
| --- | --- |
| 활성 기억 있음 | `천우가 아침에 커피를 마신다.` |
| 관련 기억 없음 | `아직 몰라. 너가 먹을 거야.` |

주어진 기억은 그대로 쓰고, 없는 것만 모른다고 한다.

## 5. 알려진 한계

- **프롬프트 제약은 보장이 아니다.** 확률적으로 줄일 뿐이며 모델·문맥에 따라 뚫린다.
  보장이 필요하면 출력 검증 같은 별도 기구가 필요하다
- 질문 3개, 모델 1개로만 확인했다. 정량 평가가 아니다
- `오늘은 그냥 있었어` 같은 약한 존재 진술은 남는다. 완전히 제거되지 않았다
- 정책을 끌 수 있게 열어두었다(`GroundingPolicy` 필드). 기본값은 전부 켜짐이며
  끄는 경로는 테스트 용도다
