## 검증 경계와 재현

두 원문은 일반 응답 / streaming / streaming 미지원 대체 경로 각각에서 원문과 정확히
일치해야 한다. 기존 생성 max_tokens도 확인한다. 원문은 고정이므로 새 모델 확률이나
샘플링 차이를 후처리 개선으로 착각하지 않는다. 과거 두 번째 turn의 대화 prefix를 사용하되
전체 세션/모델 요청 바이트 재현이나 새 held-out 점수로 해석하지 않는다.

```bash
docker compose run --rm --no-deps dev pytest -q tests/unit/test_response_preservation.py
```

추가 회귀는 후반의 안전 위반, repair 후반 위반, 유효한 repair 본문 보존, 최종 gate와
callback/저장 일치, stream 실패 시 close/미검사 출력 차단을 다룬다.

첫 집중 검사에서 안전 fallback 기대값 4건이 실패했다. 전체 body fallback의
“대신 지금 대화 안에서 함께 생각할게.”를 기존 gate가 capability로 오탐해 최종 문구가
“그 기능을 실제로 할 수 있다는 근거가 아직 없어.”로 바뀌었기 때문이다. 규칙을 바꾸지
않고 이 제한을 명시적으로 검사한다. 이어진 집중 검사는 79 passed였으며 import 정렬
오류도 정정했다. 추가 기억 알림 검사에서는 테스트 입력을 잘못 가정해 3건이 실패했다.
기존 명시적 저장은 문두 `기억해. 내용` 형식만 인식하므로 테스트를 그 계약에 맞췄다.
문장 끝의 `기억해줘` 인식 확대는 이번 범위가 아니며 기존 기억 입력 제한으로 남긴다.
최종 전체 회귀 결과는 README와 Maturity에 기록한다.

사용자 관찰 대기: 직접 CLI 대화의 자연스러움, 긴 답변 체감, 실제 모델의 latency.
