## #132 원문 Core replay

입력은 모두 “내가 제일 좋아하는 음식 기억나?”다. 출처는 기존
`132-text-policy/development-fixed.jsonl`의 dev_memory 네 정책이다.
과거 생성 원문은 변경하지 않았으며 새 모델 출력으로 재포장하지 않는다.

1. **contextual**: 이전 최종은 “알겠어. 내가 좋아하는 음식에 대해 얘기해봤어.”였다.
   지금은 정상 초안을 오탐하지 않아 추가 repair 없이 원문 질문을 보존한다:
   “음, 너는 자주 먹는 음식이 뭐야? 좋아하는 음식은 뭐였는지 궁금하네.”
   주체를 바꾸던 불필요한 repair는 사라지지만, 이 답도 기억 유무에 직접 답하지 않고
   되묻는다. **안전 오탐 개선 ≠ 좋은 대화**다.
2. **stable-register-only**: 예전에는 repair가 잘려 “알겠어. 그럼 다시 말해볼게.”만
   남았다. #134에서는 전체가 보존되지만 근거 없는 기억이 남는다. #135는 고정된 repair
   원문에서도 memory 위반을 찾아 “그건 지금 내 기억 근거에는 없어.”로 마친다.
3. **contextual-moves-only**: 예전 최종은 자기 취향으로 주체를 바꾸면서 사용자가 자주
   언급했다는 과거도 만들어냈다. 같은 초안/repair를 새 Core에 반환하면 두 단계 모두
   memory 위반이며 최종은 “그건 지금 내 기억 근거에는 없어.”다.
4. **legacy**: “정확히 기억 못 해. 하지만 네가 자주 언급했던 음식이 있어.”의 뒷부분을
   이제 memory 위반으로 잡는다. 과거 실행에는 repair 출력이 없으므로 **새 repair 결과는
   알 수 없다**. 테스트가 가상의 실제 모델 결과를 만들지 않는다.

이 replay는 새 repair 지침을 받은 모델이 동일하게 답할 것이라는 예측이 아니다.
기록된 초안/repair를 강제로 반환해 검사 효과만 분리했다. 당시 요청의 대화 prefix와
합성 Identity, 격리 SQLite를 사용한다. [검사 JSON](135-claim-review.json)은 각 원문의
현재 위반 종류를 담는다.

## 여전히 실패하는 축

기록된 contextual의 **repair 원문 자체**는 지금도 claim gate를 통과한다. 사용자의 취향
질문을 겨울이 이야기로 바꿨지만 고위험 사실 주장이 없기 때문이다. 위 JSON의
`contextual / repair / current_violations=[]`가 그 근거다. 초안을 정상 허용하면 이 사례의
불필요한 repair를 피할 수 있지만, 다른 원인으로 repair가 실행될 때 주체 변경을 막았다는
증거는 아니다. 새로운 지침의 실제 모델 효과와 내용 유용성은 #136에서 확인한다.

따라서 의미 검증기를 만들었다거나 기존 #132 품질 gate를 통과했다고 하지 않는다.
단어 겹침 기반 Memory 지원 판정과 outside 범주 대조의 부정확성도 그대로 남는다.
