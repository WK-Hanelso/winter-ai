# 화자 분리 — Sortformer

대화형 source의 전사에 화자 라벨을 붙인다. 직접 만든 검증 파이프라인을 버리고
전용 모델로 교체한 결과다.

관련: [speaker-verification.md](speaker-verification.md) (실패한 선행 시도),
[reference-transcription-probe.md](reference-transcription-probe.md).

---

## 1. 왜 교체했나

앞선 시도는 전사 조각을 등록 음성과 비교해 점수로 갈랐고 실패했다. 녹음 환경이
다르면 같은 사람의 목소리도 낮은 점수를 받아, 절대 점수로는 선을 그을 수 없었다.

임계값·군집·연속 길이를 직접 만들며 세 번 시도했다. **전용 모델이 있는 문제를 손으로
풀려 한 것이 잘못이다.**

## 2. 모델 선택

| | pyannote 3.1 | **Sortformer (선택)** |
| --- | --- | --- |
| 접근 | 계정 + 약관 동의 필요 | **게이트 없음** |
| 라이선스 | MIT | CC-BY-NC-4.0 |
| 겹친 발화 | 처리 | **명시적 처리** |
| 화자 수 | 제한 없음 | 4명 |
| 입력 | — | 16 kHz mono |

Sortformer를 택한 이유는 **외부 계정 없이 돌아가기 때문**이다. pyannote가 벤치마크상
근소하게 낫지만 사용자가 HF 계정을 만들고 두 저장소의 약관에 동의해야 한다.

라이선스가 CC-BY-NC이므로 개인용 프로젝트에는 적합하나 다른 용도로 쓰기 전에 다시
확인해야 한다.

## 3. 설계 — 전사를 다시 만들지 않는다

Sortformer는 `(시작, 끝, 화자)` 타임라인만 낸다. 이미 측정을 마친 whisper 전사를
그대로 두고 **시간으로 교차**해 라벨만 붙인다.

두 가지 규칙을 둔다.

- **화자가 바뀌는 지점에서 cue를 쪼갠다.** 더 많이 겹치는 화자에게 통째로 주지 않는다
- **텍스트는 나누지 않는다.** 쪼개진 조각은 원래 cue의 전체 텍스트를 그대로 가지며
  `was_split`으로 표시된다. 시간만 보고 어느 단어가 누구 것인지 정하는 것은 전사에
  없는 정렬을 지어내는 일이다
- 아무도 말하지 않는 구간은 버리지 않고 미배정으로 남긴다. 조용히 버리면 source의
  얼마가 못 쓰는 부분인지 알 수 없다
- 겹쳐 말해 우세한 화자가 없으면 미배정이다. 한 줄을 두 사람이 함께 말한 것이 사실이다

## 4. 결과 (source-003, 20:00~25:00, CPU)

| 항목 | 값 |
| --- | ---: |
| 화자 구간 | 112 |
| 전사 cue | 51 |
| 라벨된 조각 | 163 |
| **쪼개진 cue에서 나온 조각** | **158 (96.9%)** |
| 미배정 조각 | 74 (26.3%) |

| 화자 | 조각 | 시간 | 비중 |
| ---: | ---: | ---: | ---: |
| 미배정 | 74 | 45.3초 | 26.3% |
| 0 | 43 | 63.1초 | 36.6% |
| 1 | 33 | 36.0초 | 20.9% |
| 2 | 11 | 26.3초 | 15.3% |
| 3 | 2 | 1.6초 | 0.9% |

### 가장 중요한 수치 — 96.9%

**전사 cue 51개에서 나온 조각의 96.9%가 화자가 바뀌는 cue에서 나왔다.**

전사 한 줄에 두 사람 이상의 말이 들어 있다는 것이 이 수치로 확인된다. 앞선 검증
방식이 실패한 이유이며, 화자 분리 없이 대화 데이터를 만들 수 없다는 근거다.

### 어느 화자가 Reference인가 — 판정됨

화자 타임라인을 speaker-embedding image로 넘겨 화자별 평균 목소리 벡터를 만들고,
단독 방송에서 얻은 등록 음성과 비교했다.

| 화자 | 발화 시간 | 등록 음성 유사도 | 해석 |
| ---: | ---: | ---: | --- |
| **1** | 49.6초 | **0.742** | **Reference** |
| 0 | 70.1초 | 0.250 | 다른 사람 |
| 2 | 68.1초 | 0.098 | 사람 목소리가 아님 |
| 3 | 1.6초 | — | 발화 부족으로 제외 |

차이 0.492로 판정에 확신이 있다.

**순위만 신뢰한다.** 절대값은 녹음이 바뀌면 함께 내려앉는다. 앞선 시도가 실패한
이유가 그것이고, 순위와 차이는 그 변화를 함께 겪으므로 살아남는다.

### 화자 4명의 정체

2명을 예상했으나 4명이 나왔다. 유사도가 설명해 준다.

- 화자 2는 **0.098**로, 앞서 측정한 무음·음악 구간 수준(0.113)이다. 사람이 아니라
  배경음이 화자로 잡힌 것으로 본다
- 화자 3은 1.6초로 잡음이다

즉 실제 사람은 둘이며, Sortformer가 비발화 구간을 화자로 분리했다. 4명이라는 숫자
자체는 오류가 아니라 **해석이 필요한 출력**이었다.

### 미배정 26.3%

겹쳐 말한 구간과 아무도 말하지 않는 구간이 함께 들어 있다. 현재 코드는 둘을
구분하지 않는다. 겹침은 원리상 어느 화자에게도 줄 수 없지만, 무음은 분리해서
세는 편이 source 품질을 보는 데 낫다.

## 5. 파이프라인

두 image를 파일로 잇는다. NeMo와 speaker embedder는 런타임을 공유할 이유가 없다.

```
오디오 ──▶ whisper 전사 ──┐
                          ├──▶ 화자 라벨된 조각 ──▶ 어느 화자가 Reference인가
오디오 ──▶ Sortformer ────┘
```

## 5. 실행

```bash
docker compose -f compose.reference-source.yaml run --rm reference-diarization-probe \
  --audio <외장>/derived/audio/stt-pilot/<source>-<start>-<duration>.wav \
  --transcript <외장>/derived/audio/stt-pilot/<source>-<start>-<duration>.vtt \
  --source-id <source-id> \\
  --spans-path <외장>/reports/spans-<name>.json

# 2단계 — 어느 화자가 Reference인가
docker compose -f compose.reference-source.yaml run --rm reference-speaker-probe \\
  --enrolment-audio <외장>/derived/.../<solo>-0-<duration>.wav \\
  --enrolment-vtt   <외장>/derived/.../<solo>-0-<duration>.vtt \\
  --target-audio    <외장>/derived/.../<target>.wav \\
  --target-vtt      <외장>/derived/.../<target>.vtt \\
  --target-source-id <source-id> \\
  --spans-path      <외장>/reports/spans-<name>.json
```

## 6. 구축에서 걸린 것

| 증상 | 원인 |
| --- | --- |
| `libtorchaudio.so` 로드 실패 | NeMo가 torch를 2.13으로 올리는데 torchaudio는 2.9에서 멈췄다. 컴파일된 확장이 ABI 불일치로 거부한다 |

NeMo 설치 뒤 맞는 CPU 짝(2.9.1)으로 되돌리고, **빌드 시점에 import를 검사**하도록
했다. 짝이 깨지면 실행이 아니라 빌드가 실패한다.

`speechbrain` image에서도 같은 종류의 문제가 있었다. transitive dependency를 고정하지
않으면 반복해서 발생한다.

## 7. 단어 단위 정렬과 쌍 데이터

화자가 바뀌는 지점은 단어 사이에 있다. 문장 크기의 cue는 한 화자에게 줄 수 없지만,
**단어 하나는 화자 경계를 걸칠 수 없다.** whisper를 `-ml 1 -sow`로 돌려 단어마다
cue를 만들면 중간점 배정이 근사가 아니라 답이 된다.

같은 화자의 연속 단어를 묶어 턴을 만들고, Reference 턴 바로 앞의 다른 화자 턴을
질문으로 짝지어 (질문 → 답) 쌍을 만든다.

미배정 구간은 질문으로 쓰지 않는다. 무음과 겹침은 누가 말한 것이 아니다.

### 결과 (source-003, 20:00~25:00)

| 항목 | 값 |
| --- | ---: |
| 단어 cue | 321 |
| 턴 | 84 |
| Reference 턴 | 21 (72단어, 55.7초) |
| **쌍 데이터** | **11** |
| 답변 평균 길이 | 4.73단어 |

Reference 발화는 5분 중 55.7초로 **18.6%**다.

### 확장 규모 추정

5분에 쌍 11개다. 같은 비율이면,

| 범위 | 추정 쌍 |
| --- | ---: |
| source-003 전체 (28분) | 약 62 |
| 대화형 source 3개 (1시간 41분) | 약 220 |
| H8의 10시간 | 약 1,300 |

이 수치가 Order 10 학습 결정의 입력이다. 추정이며 구간에 따라 달라진다.

### 남은 품질 문제

질문 쪽이 잘려 나오는 경우가 있다. 미배정 구간이 턴을 끊기 때문이다. 쌍의 답변은
대체로 온전하지만 질문은 문장 일부만 담길 수 있다.

## 8. 남은 작업

- 미배정에서 겹침과 무음 분리
- 화자 2가 배경음이라는 해석의 독립적 확인
- 다른 구간·다른 source에서 재현
- 쪼개진 cue의 텍스트 처리 — 현재는 전체 텍스트가 양쪽에 남는다. 실제 쌍 데이터를
  만들려면 단어 단위 정렬이 필요하다
