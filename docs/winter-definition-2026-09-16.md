# winter-ai 정의와 로드맵 (2026-09-16 재정의)

이 문서는 2026-09-16 천우의 요구("정의부터 다시 해. 목적이 뭐고 궁극적 형태는 뭐야")에 따라
지금까지 천우가 말한 것과 저장소 기록만으로 다시 쓴 기준 문서다. 이후 우선순위 판단은 이 문서를 따른다.
기존 `docs/roadmap.md`의 8월 계획(Level 3 공동 자기발전, Milestone 4~7)은 폐기가 아니라 이 정의 아래로 재배치된다.

## 1. 목적

천우 한 사람을 깊이 이해하고, 천우가 소유하는 AI 존재를 만든다.
겨울이는 대화 상대이자 같이 사는 동반자이고, 필요한 것을 스스로 알아보고 처리하는 에이전트이며,
자기 자신을 관찰하고 개선하는 존재다. 남의 서비스가 아니라 천우의 기계 위에서 천우의 규칙으로 큰다.

천우의 말(2026-09-13~16):
- "너라는 겨울이란 아직 사람은 아니지만 혼자 발전하고 감정 같은 것을 갖는 그런 AI를 만들려고 하는 거야."
- "나, 이천우라는 사람을 더욱 이해하고 나랑 같이 살아가는 AI."
- "내가 말한 것을 분해해서 정보로 받아들이고 구분해서 DB에 저장한 뒤 그걸 기반으로 답해야 한다. 이전 기억까지도."
- "정보를 알아올 수 없는데 어떻게 agentic이야."
- "묻지 않고 기억하게 해. 편의성이 제일이야."

## 3. 하드웨어 전제

- **RTX 2060 (6GB)**: 지금 로직을 맞추는 테스트 자리. Qwen3-30B-A3B Q4_K_M, 전문가 44층 CPU, ubatch 512. 첫 글자 3~4초(warm).
- **RTX 3070Ti (8GB)**: 본 실행 후보. 전문가 층 GPU 승격 또는 밀집 14B급 전량 GPU. 프롬프트 처리·생성 2~4배 → 턴당 도구 호출 예산 2회 → 3~4회("검색 → 읽고 → 다시 검색 → 답").
- **Jetson Orin**: 24시간 상주 자리. 대화가 없는 시간의 기억 정리·검색·자기 점검·개선 제안(축 3)을 여기서 돌린다. 8월 분석 부하 재부팅 기록은 부하 관리 문제이지 설계 제외 사유가 아니다.
- 모델 서버는 `WINTER_LLM_URL` 하나로 교체된다. 판단·기억·일정·검색·위임은 전부 서버 밖 파이썬이라 하드웨어를 바꿔도 코드는 그대로다.

## 3-1. 모델 전략 — 지금 모델은 천장이 아니라 현재 제약의 최선

천우의 말(2026-09-16): "2060에서 Qwen을 돌리는 이유는 메모리 때문이지 만족한 건 아니다."

- 모델은 부품이다. 지금 Qwen3-30B-A3B Q4_K_M은 6GB에 들어가는 선택이지 목표가 아니다.
- 하드웨어가 열릴 때마다 후보를 **같은 실제 장면(P2 6장면·P3 7턴·기억 회상·검색 판단)**으로 다시 재고 더 나은 쪽으로 올라간다. 기준은 판단 정확도(도구 호출·일정·기억)와 첫 글자 지연이다.
- 후보(측정 전 가설, 확정 아님): 3070Ti 8GB에서는 30B-A3B의 전문가 층을 GPU로 더 올린 구성 vs 밀집 14B급 Q4 전량 GPU; Orin에서는 통합 메모리 크기에 따라 32B급 밀집 Q4까지. 새 모델이 나오면 후보에 넣는다.
- 모델을 바꿔도 기억·일정·검색·위임·자기개선 로직은 그대로다. 그래서 지금 2060에서 로직을 먼저 맞추는 것이고, 모델 상향은 그 로직을 그대로 들고 간다.
- "우리 하드웨어라서 안 된다"는 말은 이 프로젝트에서 금지한다. 안 되면 무엇이 부족한지(메모리·처리량·모델 판단력) 숫자로 말하고 그걸 채우는 단계를 계획에 넣는다.

## 4. 순서 (2026-09-16 이후)

각 단계는 "실제 원문·DB 변경·지연"으로 검증하고 천우가 실사용으로 채택 판단한다(토론 verdict 쟁점 5 유지).

0. **P8 웹 검색 + P8.1 SelfModel 정리** (진행 중) → 재시작 → 실사용 관찰 며칠. 판단 기준: 어제 말한 걸 오늘 아는가, 답이 3~5초에 시작하는가, "모른다"가 줄었는가.
1. **축 1 마무리 — 기억 정리**: 모순 해결(예: SWM 재직 vs 한양이엔지 이직), 오래된 상태의 만료, 문서성 기억 분리, 겨울이 자신에 대한 기억(축 4의 데이터 기반) 저장. 검색 결과는 기억과 분리 유지.
2. **축 5 — 말투 습관(P3-1d)**: 빈 칭찬·없는 경험을 샘플링 층(logit_bias)과 예시로 잡는다. 실사용 로그가 근거.
3. **축 2 확장**: 3070Ti로 옮긴 뒤 도구 호출 예산 3~4회, 파일 읽기·알림 손 추가. 코덱스 쓰기(파일 수정)는 승인 후 격리 Worker로 — 축 3의 입구.
4. **축 3 — 혼자 발전 (Orin)**: 유휴 시간 루프 = 기억 정리 → 실패 턴 분석(관찰 로그) → 개선 제안 작성 → 다음 대화에서 천우와 토론 → 승인 → Codex Worker 구현·검증 → 채택/롤백. 8월 `improvements`·`owned_work`·worker gateway를 text 경로에 다시 연결한다.
5. **축 4 — 감정·자기 상태 모델**: 겨울이의 상태(기분·관심·최근 사건)를 데이터로 두고 세션을 넘겨 이어간다. 근거는 실제 사건(대화·작업 결과)만.

## 5. 지금까지 한 일 (2026-09-12~16, 로컬 커밋, push 없음)

P-1 정리·테스트 격리 → P0 계약·계측 → P0.5 게이트 강등·재배치 → P1 일정 저장소 → P2 일정 대화(4회 반복, 오류 0) → P3-1 말투 1차(프로필·Identity v3·산문 기억·반복 안전장치) → P4/P4.1 자동 기억 배선 → P5/P5.1/P5.2 지식 기억(분해·시각·선택) → P3-2/3/4 지연(스트리밍·캐시 배치·ubatch: 첫 글자 35~73s → 3~4s) → P6 코덱스 오발동 수정 → P7/P7.1 모델 판단 위임·일정 날조 방지 → P8 웹 검색(진행).

## 6. 하지 않는 것

- 하드웨어 상한을 2060 기준으로 말하지 않는다.
- 규칙(정규식) 추가로 판단을 대신하지 않는다. 판단은 모델 출력 계약(JSON 필드)으로, 실행·검증은 파이썬으로.
- 승인 게이트를 편의 흐름에 끼워 넣지 않는다(되돌릴 수 없는 것만).
- 실제 원문 없는 점수 보고를 근거로 쓰지 않는다.
