# ADR 0039 — 대화 능력 확보와 형체 없는 겨울이의 표현 경계

- 날짜: 2026-09-11
- 상태: 사용자 승인 전략. 모델 채택·학습·Voice activation 승인이 아니다.
- 연결: Epic #127, 현재 진단 #137, 기존 T2 및 T3/T4/T5/T6.

## 배경과 결정

사용자는 Gemini의 제안을 함께 검토한 뒤, 엔진 규칙 보완만이 아니라 관계형 한국어 대화에
적합한 모델과 예시 데이터를 확보하는 일을 중심 과제로 올리기로 했다. 겨울이는 형체 없는
프로그램이며 사용자와 대화한다. "등을 기대며" 같은 몸/공간 지문은 기본 대화에 의미가 없다.
한숨·웃음·머뭇거림은 이후 Voice에서 실현 가능한 선택적 발화 전달 정보로 구분한다.

목표는 상담형 문장을 반말로 바꾸는 것이 아니라 농담→진지함 전환, 복합 의도, 자기 관점,
정정 수용과 실제 기억을 반영하는 대화 행동이다. 없는 과거·실행·몸의 활동을 꾸미지 않는
경계와 자연스러움을 별도로 평가한다. 정렬 제거가 대화 능력의 핵심이라는 가정은 채택하지 않는다.

## 실행 순서와 중단 기준

1. #137: 같은 모델·입력·선택 근거의 최소 지침/전체 Core 원 출력을 제한 비교한다.
   여기서는 새 regex, repair, 모델 다운로드와 운영 gate 해제를 하지 않는다.
2. T2.7: 공개 코드/weight·한국어 다중 턴 근거·라이선스·장비 조건으로 소수 모델 후보와
   예시 데이터 접근을 조사한다. Qwen 재선정은 전제하지 않는다. 기존 실패한 범용 모델의
   동급 순회는 새 조건과 근거 없이 반복하지 않는다. 조사와 다운로드/실측 scope를 구분한다.
3. T2.8: 별도 Issue에서 소수 후보를 동일 문맥으로 비교하고, 필요하면 no-example/few-shot을
   분리한다. 이전 개발 실패와 새 평가 장면을 구분하고 먼저 rubric을 고정한다.
4. T2.9: 선택 근거가 있는 모델과 최소 필요 문맥으로 기존 CLI의 작은 대화 경험을 검증한다.
   자동 검사 성공과 천우의 실제 선호를 분리한다. 실패가 이어지면 원인/선택지를 보고하고
   무한 prompt 튜닝 대신 다음 scope를 합의한다.
5. T3/T4: 짧은 대화 기준선 위에서 검색·정정·재시작 연속성을 개선한다. 기존 기억 기능은
   계속 유지하며 완벽한 모델을 기다리느라 독립적으로 유용한 기억 작업을 무기한 미루지 않는다.
6. T5/T6: 승인된 외부 Worker 경험을 통합한다. 반복 대화 실패에 대한 SFT/선호 학습은
   별도 데이터·평가·장비 scope로 결정하며 Worker 통합의 필수 선행조건으로 두지 않는다.

## 재사용과 보류

- Shared Core, Identity, SQLite, ContextAssembler, 모델 Port와 과거 실패 기록을 보존한다.
- 계층형 문맥은 정체성 + 필요한 기억 + 최근 대화로 구성하되 원문을 요약으로 대체하지 않는다.
  원문 참조·정정·유효 상태·토큰 예산을 함께 관리한다. 고정 20턴과 Vector DB를 필수화하지 않는다.
- 현 llama.cpp를 즉시 vLLM으로 바꾸지 않는다. runtime/양자화 변경은 실제 호환성·latency 근거로
  결정한다. 이번 전략 변경은 개인 DB migration이나 외부 모델 API 사용 승인이 아니다.
- Human Reference 결합 원본은 로컬에 보존한다. 텍스트 평가/예시 view에서 관찰된 한숨과
  추정한 감정을 구분하고, 자료를 바로 학습 데이터로 확정하거나 Git에 올리지 않는다.
- 예시 자료는 말투뿐 아니라 문맥과 반응을 포함한다. 2,000~5,000 rows나 특정 LoRA 모듈을
  미리 정답으로 정하지 않는다. 배포용 양자화 결과도 별도 평가해야 한다.

## 발화와 전달 계약 — 설계만, 미구현

공유 lexical response는 하나다. CLI는 기본적으로 텍스트를 출력하며 전달 표시는 선택 사항이다.
Voice는 같은 문장을 다시 쓰지 않고 공통 전달 metadata를 자기 runtime의 token/audio로 변환한다.
한숨·웃음·pause는 생물학적 경험의 주장이 아니며 매 턴 강제하지 않는다. 지원하지 않는
효과는 생략하고 문장을 유지한다. 특정 TTS 토큰을 Core의 공통 규약으로 고정하지 않는다.
기존 CompanionResponse/ProsodyPlan 재사용 가능성을 우선하며 이번에는 새 필드를 추가하지 않는다.

## 근거와 한계

- 사용자: 2026-09-11 본 대화에서 전략과 전달/신체 지문 경계를 합의하고 다음 작업을 승인.
- [#136 평가](../evaluations/136-text-reevaluation/README.md): 모델의 없는 기억 생성과
  검사기의 정상 설명 훼손을 모두 관찰했다. 전체 제품 품질이나 단일 원인의 증거는 아니다.
- [제타 개발 인터뷰](https://blog.scatterlab.co.kr/interview-mlresearch): 자체 모델·제품 피드백의
  연결 근거. 제타 내부 구조를 그대로 안다거나 Polybuzz에도 동일하다고 주장하지 않는다.
- [제타 DPO 기록](https://blog.scatterlab.co.kr/유저와-함께-만드는-llm-제타에-preference-optimization-도입하기-172134):
  선호 신호 정제와 안전성 보완. 알고리즘 도입만으로 품질이 보장되지 않는다.
- [PEFT](https://huggingface.co/docs/peft/developer_guides/quantization): 학습은 선택지이며
  이 전략은 QLoRA 장비 적합성이나 학습 성공을 검증하지 않았다.

기존 문서의 T2→T3 순서를 위 후속 단계로 보완한다. 과거 완료/실패 판정은 수정하지 않는다.
Text-first maturity는 contract이며 사용자 관찰 대기와 기존 activation gate를 유지한다.
