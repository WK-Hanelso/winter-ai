# ADR 0037 — 주장 표현과 근거 승인 분리

- 날짜: 2026-09-11
- 상태: #135 구현 범위 채택. 대화 품질/repair 의미 보존의 성공 판정은 보류
- 선행: #132 실제 출력, #134 전체 응답 보존, [ADR 0036](0036-preserve-reviewed-response.md)

## 문제

기존 gate는 질문도 외부 사건으로 검사했고, 문장 안의 부정 하나가 다른 주장까지 면제했다.
자기 생각을 말하는 문장이 실행 약속으로 잡히고, “기억이 있어 / 자주 언급했던” 같은
과거 귀속 표현은 누락되었다. 모든 인용 내용을 지워 Memory 근거 대조도 왜곡했다.
잘못된 repair가 사용자의 취향 질문을 겨울이 취향 이야기로 바꾼 실제 출력도 있다.

## 결정

- `dialogue/claim_language.py`는 질문 형식, 확인/과거 전제, 인용 구간, 명시적 대조절과
  능력 동사 표현을 다룬다. `ResponseClaimGate`는 기존 근거 승인과 종류별 처리를 소유한다.
- 출력 문장을 다시 쓰지 않는다. 검사에만 문장/명시적 대조절 view를 사용하고, 인용 내부
  마침표는 경계로 삼지 않는다. 가짜 placeholder 치환 대신 원문 구간을 사용한다.
- 열린 정보 질문은 outside 사실 주장과 구분하지만, “맞지?”와 과거 전제는 자동 면제하지
  않는다. 질문 형태의 사용자 문장은 자기 질문의 전제를 승인하는 근거로 쓰지 않는다.
- 부정은 나뉜 검사 단위 안에서만 적용한다. Memory 과거 귀속 표현을 확장하고 현재 사용자
  진술의 재귀속은 질문이 아닌 현재 발화로 대조한다. 명시적 기억 주장은 기존 Memory 근거를
  요구하며, memory capability와 실제 저장 권한의 구분도 유지한다.
- 신체 검사에서는 인용을 제거하되, 실제 Memory 내용 대조에는 인용 원문을 포함한다.
- 자원 명사 근처의 모든 `할게`를 능력 주장으로 보지 않는다. 실행/대화/기억 등 capability
  동사 표현을 확인하며 `생각할게`는 실행 약속으로 분류하지 않는다. 특정 음식/장면 예외는 없다.
- 안전 repair 지침에 원래 질문의 대상·주체·목적과 직접 답변 보존을 명시한다. Core의
  원 질문/문맥, 최대 한 번 repair, 전체 final gate, 저장/callback 순서는 변경하지 않는다.
- fallback을 검사에서 면제하지 않는다. 전체 fallback 5종을 실제 gate로 재검사한다.

## 명시적인 한계

이 변경은 여전히 **제한된 어휘/표현 기반 검사**다. 한국어 의미 분석 모델이나 일반적인
사실 검증기는 아니다. 인용 범위/대조절·생략 주어·복잡한 부정, 목록 경계와 표현 변형을
완벽하게 처리하지 않는다. 기존 Memory의 단어 겹침 및 outside의 범주 단위 대조도 진짜
함의 검증이 아니다. 같은 주제의 다른 사실을 틀리게 말하는 실패가 남을 수 있다.

특히 “내가 좋아하는 음식은 피자야”는 겨울이 자신의 취향 표현으로는 gate 밖이다.
사용자의 취향을 묻는 질문에 그 말을 답하는 오류까지 claim gate에 집어넣지 않는다.
repair 지침 추가는 해결 가설이며, 새 모델 출력으로 의미 보존을 확인한 것은 아니다.
질문 되돌리기/서론뿐인 답변/주체 변경은 #136 실제 내용 평가에서 별도로 판정한다.

## 검증과 인계

[전후 결과와 잔여 실패](../evaluations/135-claim-review.md),
[실제 과거 출력 검사 자료](../evaluations/135-claim-review.json)를 따른다.
v1/v2 장면은 그대로 보존하고 31개 사전 대조, 5개 replay/근거 검사 및 최종 신체 부정형
대조 2개를 추가했다.
새 LLM 호출, 외부 API, DB migration, 서비스 재배포는 없다. legacy 기본값과 Text-first
contract를 유지하며, rollback은 #135 코드 변경을 되돌리는 것으로 데이터 복구가 필요 없다.
